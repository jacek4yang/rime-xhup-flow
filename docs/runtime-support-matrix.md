# 当前运行时能力与证据边界

这是当前实现的支持边界，不是某个 RC 已通过验收的证明。每份发布证据必须
绑定源提交、生成包/安装物 SHA256、librime/Lua/前端版本与实际运行日志。
开发分支、历史 RC 或一次 focused 测试均不能自动获得稳定版资格。

| 表面 | 当前实现/边界 | 如何验证 |
| --- | --- | --- |
| Static | 独立零 Lua 的精确码兼容锚点 | 冻结映射及完整静态菜单清单 |
| Flow | 静态菜单优先；原生候选 + 有界结构分段 | 真实逐键、编辑、部分选择、最终提交及静态前缀审计 |
| 原生学习 | 唯一持久写入器 `xhup_flow_user`；API/存储/配额约束 | 实际上屏后导出计数、重启、配额拒绝前后字节相同 |
| 旧 Lua | 能力探测，不按版本名猜 API；不满足有界学习接口时只读并显示原因 | 真实旧绑定输入、状态、无学习条目及重启不写入 |
| 上下文调序 | 默认关闭，最多一个全局候选头；固定层受保护 | Lua 边界/尾流身份测试 + 真正 librime 菜单 |
| 会话记忆 | 默认关闭；同意后有界进程内状态，关闭即清理；不落盘 | 不观察关闭态提交、会话隔离、重启为空、旧 TSV 不变 |
| joint decoder | **未交付实时联合解码器**；开关/引擎注册已移除 | 包含的同名文件仅为覆盖旧安装的不可用兼容 shim |
| Rust decoder/优化器 | 离线研究；分位效用不是概率，有限 beam 不是最优解保证 | caller-objective/穷举对照/证据消融，不冒充 live 菜单 |
| Trainer | 构建时包与哈希清单；运行时只读缓存；诊断区分文件、配置、live 证据 | 包清单与安装故障回归；无法观察 live 时保留 Unknown |
| 安装与学习管理 | 自有文件范围、排他暂存、合作锁、失败回滚/拒绝；不保证断电事务 | 故障注入、锁占用、外来/符号链接拒绝、前端实际部署 |

## 输入与资源契约

Static 精确菜单兼容不等于主方案每个中间 preedit 都与旧方案一致。
词表外内容可逐字/分段输入；歧义拼音整句是否出现在有限候选头、是否首选，
需要独立质量评估，不能从“有单字原语”推导任意整句可达/首选。
边界规划是结构启发式，不是已交付的联合语言模型。

Flow 使用一个原生组句/学习编译表；源 Flow YAML 仍完整导入，未删词来缩表。
部署峰值、持续输入、长输入和尾延迟是不同指标。循环/候选/学习配额的逻辑上界
不等于所有硬件达到某个毫秒预算。详见 [资源策略](runtime-resource-policy.md)。

## 验证分层

- 纯 Rust/Lua stub：领域、资源和故障契约，不代表 librime 已执行。
- 原生 focused：验证指定行为；未跑全静态/扩展清单就必须标注未跑。
- 全量清单：核对完整输入/输出行数，零错误；绑定实际生成字节。
- 外部质量：固定输入与选择规则、保留所有失败样本、列出域偏差与训练重叠；
  in-sample 基线和定制回归不得冒充独立会话质量。
- 产物：清洁生成、实际安装物内容/许可/哈希、构建来源与不可变 RC。
- 平台用户验收：Windows/macOS 由用户按 [README](../README.md#支持平台)
  测试；没有反馈就保持待测。Linux/Android 也不能用编译替代交互验收。
- 稳定晋升：schema 2、真实 RC 源与附件、逐平台证据必须齐全；
  当前工程任务不授权发布稳定版。

`architecture.md` 保留早期设计背景，`architecture-v2.md` 保留研究目标；
其中目标图、旧双 translator 描述、旧快照或开关不构成当前支持承诺。
`release-readiness.md` 的历史记录必须按其标注的版本阅读，不能跨 RC 继承通过。
