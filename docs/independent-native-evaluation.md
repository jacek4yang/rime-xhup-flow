# 外部文本原生评估协议（结果测量前固定）

本评估补充原生行为回归，不代替真实用户验收，不宣称“完美输入法”。
输入源为 Universal Dependencies Chinese-GSDSimp r2.16 的 test 文件，
固定提交、SHA256、作者、许可边界见 `tests/quality/ud-source.json`。
这是外部维基文本，不是中文会话的代表性随机样本；尚未证明与所有上游
词频/训练文本无重复，不能称严格训练隔离的 held-out 质量估计。

## 固定选择与输入

只使用源文件已有 Translit，不根据当前词典、候选名次或预期输出猜读音。
从 Rust 规范音节编码器导出 406 个音节双拼码；按汉字数约束解析拼音，
多解/缺失/不支持的 token 必须排除并计数，绝不选择有利于当前系统的一解。
保留所有连续合格汉字 token 串，长度 2–64 字；标点、混合文字、不支持的
token 切断串。每个原始句子的所有串保留 parent sentence 标识。

源文件留在本地缓存，不随生产包分发。UD 标注 CC BY-SA 4.0，
底层维基文本另有原作者归属/许可；本仓库只提交协议、工具、摘要和源哈希，
不将下载到的公开文本宣称为自行创作或无版权。

## 原生运行与消融

使用 source-byte gate 校验生成包中的 8 个 Lua 模块及 2 个方案；
隔离目录重新部署，验证编译后所有 native user dict 开关关闭；
关闭上下文调序、会话记忆、提示，不读取真实用户目录。

两组固定比较：planner 为生产边界规划；native-only 只通过测试包装器移除
规划器的 lookup memory，保留同一原生 provider、词典、过滤链及基础候选流。
包装器仅存在测试目录，不能进入生产包。实际编译后的 provider 必须与报告
模式相符。不得按这组测试结果调参后继续将它描述为未见过的测试集。

每键记录原始输入、preedit、前16项、目标在前256中的名次及耗时。
结束后记录 top1/top3/top256；未出现是质量失败样本，不得删除或改成通过。
对可达目标实际选中，验证精确提交、输入耗尽、无重复提交。
硬行为检查覆盖每键不丢码/不提前提交、退格恢复、重新输入恢复、
增加一个待续键后撤回的状态恢复。待续目标可达率另行报告，不预设歧义输入
一定选中某个文本。质量统计与硬行为错误分开。

摘要必须包含所有排除计数、长度/专名分层、按原始句子聚类的固定 seed
bootstrap 区间、两组配对差异、源码/包/轨迹哈希和实际 librime/Lua 版本。
耗时包含真实菜单生成，但前256探测单独统计；并发全量审计期间的测量
必须标注机器负载，不能作为无负载生产性能保证。

## 已知训练文本重叠审计

另行按固定提交与 SHA256 读取 KDConv 全部九个 train/dev/test 文件和 PTT 原始文本，
使用仓库既有抽取脚本；PTT 的 OpenCC 固定为 0.1.7。检测前统一 NFKC 并保留字母数字，
逐例报告与完整训练句子等值、以及共享连续 8 字跨度（保守重叠提示，不等于语义抄袭）。
短于 8 字的案例仍记录精确等值，不凭空计为通过近重复检查。所有原始案例继续留在
主质量分母，不因观察到名次或重叠而剔除；另报没有这些已知重叠的子集。
这不能证明万象等词频源未见过原文，也不能将“无已知重叠”改称绝对无污染。

## 复现

```sh
cargo run --locked -p xhup-core --example syllable_codes > syllables.tsv
python3 tests/quality/prepare_ud_corpus.py SOURCE.conllu syllables.tsv fixture.tsv metadata.json
XHUP_AUDIT_ONLY_REPLAY=1 XHUP_REPLAY_CORPUS="$PWD/fixture.tsv" \
  XHUP_CORPUS_MODE=planner tests/librime/run-flow-audit.sh GENERATED > planner.jsonl
# 同样命令切换 XHUP_CORPUS_MODE=native-only，使用另一干净部署。
```

## 第一轮完整结果：发现排名退化，不是 GA 通过

两组均完成全部 1,821 串：planner 13,308 项硬行为检查、native-only 13,203 项，
均零输入/编辑/提交失败。额外检查数量取决于目标是否可达，不是更大组获得加分。

| 模式 | 整串首选 | 前3可达 | 前256可达且实际精确提交 | 增加待续键后目标仍可达 |
| --- | ---: | ---: | ---: | ---: |
| 原结构规划器 | 33.94% | 45.09% | 46.07% | 37.45% |
| 原生基础流 | 41.13% | 44.04% | 44.92% | 8.84% |

结构规划提高前缀续输与少量目标可达性，却损害首选：**−7.19 个百分点**。
这不是“所有问题已解决”，不能只引用零硬行为失败就宣称质量通过。
完整分层与配对聚类区间见
[结果 JSON](../data/benchmarks/native-source-external-v1.json)，
[包/环境身份](../data/benchmarks/native-source-external-v1-environment.json)。
并发负载不同，耗时不可作为两模式无负载性能优劣结论。

已知训练重叠审计完整扫描 92,558 条 KDConv 句子、861,745 条 PTT 句子：
分别有 15/34 个精确等值案例、各 1 个共享 8 字跨度案例；并集 37 例。
所有案例仍在总分母中；无这些已知重叠的 1,784 例另行报告，
其中长度至少 8 字的 794 例也单列。未证明未知词频源没有见过这些文本。

**后续若据此修正规划器，本集合变为已见诊断/回归集。** 第一轮冻结结果
必须保留，后续分数不能继续称作未见 held-out；还需新的独立来源或前先固定的
未使用分割来评估修改的泛化。当前改进方向是保留原生优先次序而非给结构候选
任意加分，不针对词形添加特例。

## 冻结的新确认分割：保留原生前缀后的完整结果

修正仅保留原生前五候选、移除结构候选的人工质量加分，再追加有界补充候选。
在观察新分割的任何排名前已固定
`tests/quality/ud-confirmation-source.json` 及策略 SHA-256
`4dd7e514006152d2ddc497413136388ab3a3765aec6a8be8ce504cd760a17f6d`。
上游文件名虽然是 dev，这里没有用它调参；第一轮 test 文件现在仅是已见回归集。

确认分割 500 个句子、全部 1,883 个合格串均完成。
planner 13,778、native-only 13,688 项真实输入/编辑/提交检查均无失败：

| 模式 | 整串首选 | 前3可达 | 前256可达且实际精确提交 | 增加待续键后目标仍可达 |
| --- | ---: | ---: | ---: | ---: |
| 保留原生前缀的修正策略 | 42.33% | 44.77% | 46.26% | 38.71% |
| 原生基础流 | 42.33% | 44.77% | 45.30% | 9.45% |

配对句子聚类 95% 区间：首选/前3差值均 [0,0]；前256/精确提交提升
0.96 个百分点，区间 [0.53,1.43]；待续可达提升 29.26 个百分点，
区间 [27.09,31.47]。逐例核查原生前五内的 **851 例排名全部不变**，
不是用净提升抵消个别伤害。`--require-native-prefix` 将任何逐例变化视为失败；
汇总还拒绝硬行为失败，但保留负面报告用于诊断。

[完整确认报告](../data/benchmarks/native-source-confirmation-v1.json) 包含全部
长度/专名/已知训练重叠分层与时间；[包/环境身份](../data/benchmarks/native-source-confirmation-v1-environment.json)
绑定实际生成文件和测试运行时。原负面结果保持不变，不覆盖成“原本通过”。

**解释边界**：这是同一百科域的新分割，不是独立聊天总体，也不能证明
未知词频上游从未见过文本。长句和专名准确率仍明显较低，不能把 42.33%
整串首选宣传为“完美输入”或训练器短词准确率。耗时含并发审计负载，
不用于承诺所有用户设备的延迟。这里只证明本轮修复没有重演所观察的
首选损害，并提高部分候选/待续可达性；完整静态审计和平台验收另行绑定。

## PUD 合法全码/混码评估准备

旧 GSDSimp 开发与确认集合均已被观察，不再作为未见证明。`4b89049` 在读取
新语料或运行候选前冻结 `tests/quality/pud-legal-source.json`：上游
Chinese-PUD `2849afd946a8c01b3e9acdf3e7afa8670cf2777d`，CC BY-SA 3.0，
以及五层静态词典 SHA-256。语料仅用于外部评估，不进入生产词典、模型或安装包。

`prepare_legal_corpus.py` 使用原始 UD 词边界，为每个合格汉字串生成全字全码、
交替简码/全码、逐词最短合法码三种输入。选码只依据冻结规范表，不查看候选
排名；多音字使用合法四键码，不把自动猜测读音当作独立标注。父句 SHA256
决定开发/确认分区，所有模式和片段随父句分组。三种模式必须分别报告；
同码重复保留，但不能混算为独立样本。

首次准备真实处理1000句、21415词，合格350串、每模式350例，共1050例；
开发519例、确认531例。2438串因缺少合法四键字码、226串因长度范围而排除，
原文及原因全部保存在元数据，不截短、不删除不利结果。此次合格覆盖有限，
不能外推为一般中文质量；未进行繁简转换，也没有因覆盖低而改写冻结选择规则。
源文件、上游许可/署名、规范表、准备程序和最终fixture均有摘要；独立重建必须
匹配已冻结fixture与分区摘要。此前词频/训练数据重叠仍须单独报告。

`run_native_corpus.py` 为已部署的合成测试包创建无用户数据库的隔离副本，
绑定已提交的原生驱动、公开fixture、插件和全部部署文件，执行逐键、退格、
待续及实际选中提交。两/三键合法输入不再被旧的四键语料下限拒绝。输出保留
所有排名缺失和硬合同错误；进程成功仅表示硬合同检查通过，不表示首选合格、
完整回归通过或 GUI 验收。运行时间仍只是观察值，不能替代无负载配对性能。

统计合同现在使用准备程序记录的实际 `keys` 长度，不再假设每字恰好两键；
旧元数据须从固定源重新生成，不能推算或伪造混码按键数。真实空候选窗口
可能报告页长0：只有同一案例最终逐键帧同时证明空菜单、页长0和完整原始
输入长度时才接受，并计为候选缺失；缺少证据或非空窗口的非法页长仍失败。
这不是放宽首选指标，也不从分母删除空候选案例。
