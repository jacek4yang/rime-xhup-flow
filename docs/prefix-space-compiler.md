# Prefix-Space Compiler v3 设计与基准报告

本文档阐述 XHUP Flow 2.0 阶段的核心组件：**Prefix-Space Compiler v3**。

## 1. 核心模型与不变量

### 1.1 前缀闭合变长码空间 (Prefix-Closed Code Space)
与将简码视为孤立离散分配的传统方案不同，v3 编译器将整个小鹤音形键位空间形式化为**前缀闭合 Trie 树**。
对于任意合法码路径（如 `uior`），其所有前缀状态必然在码空间中自然闭合且可合法查询：

```text
"" (root)
 └─ u (有 / 时间 rank 2 ...)
     └─ ui (时间 rank 1 / 输入 rank 2 ...)
         └─ uio (输入 rank 1 ...)
             └─ uior (输入法 exact ...)
```

### 1.2 核心不变量：valid prefix != commit boundary
- **有效短前缀不因首选候选而自动上屏**：用户输入 `u` 时，虽然界面显示 rank 1 候选（如 `有`），但只要子树存在后续分支路径，用户敲击下一键 `i` 即可平滑进入 `ui` 状态。
- **提交发生于显式按键（如空格、选择键或回车）**，而非因前缀合法性被动截断。

### 1.3 码位候选槽位模型 `(code, rank)`
- 码位不被单一单词独占，而是表示为有序候选槽位集合：
  - `u`: rank 1 = `有`, rank 2 = `时间` ...
  - `ui`: rank 1 = `时间`, rank 2 = `输入` ...
- **多前缀阶梯可达**：同一个目标词（如 `时间`）可以在多个前缀长度（如 1 键、2 键、4 键）以不同 rank 阶梯可达，用户既可通过超短简码次选输入，亦可在两键快速首选输入，或直接全码盲打。

## 2. 全局多目标优化与成本函数

v3 放弃单一 KSPC 指标，建立综合考虑输入质量与认知负担的确定性全局目标函数：

$$\text{Net Utility}(t, c, r) = \text{Benefit}(t, c, r) - \sum \text{Costs}(t, c, r)$$

### 2.1 收益项
- **综合频率质量 $M(t)$**：结合万象全局词汇频率与会话域（如 KdConv）频率，采用中位锚定无量纲化：
  $$M(t) = w_{\text{lex}} \ln\left(1 + \frac{f_{\text{lex}}}{f_{\text{ref,lex}}}\right) + w_{\text{conv}} \ln\left(1 + \frac{f_{\text{conv}}}{f_{\text{ref,conv}}}\right)$$
- **预期击键收益**：节省按键 $\Delta K = (\text{len}(t.\text{full\_code}) - \text{len}(c))$，加权收益为 $M(t) \cdot \Delta K \cdot k_{\text{key}}$。

### 2.2 成本与惩罚项
1. **候选位名次选择成本**：rank 1 为 0，rank 2~4 逐级递增（需数字键或额外翻页选择）。
2. **码位碰撞成本**：同码既有占用质量带来的选择歧义与认知搜索负担。
3. **前缀拥塞惩罚**：经过该前缀的子树总流量；短前缀（1~2 键）拥塞对整体流畅度惩罚更高。
4. **子树/邻域外部性**：在前缀处放置候选对后续长词输入者的视线干扰。
5. **分段歧义性**：短码若与常用音节/字首高度重叠，给后续连续连打分段器带来的歧义代价。
6. **XHUP 规则偏离惩罚**：优先保护官方/attested 规则与系统性单调缩写（$F^* I^*$），重罚不合规码。
7. **肌肉记忆迁移惩罚**：保护既有 v1/v2 习惯，对剥夺或大幅重置既有简码施加迁移阻力。

## 3. 确定性求解器：迭代重加权槽位分配

为避免引入外部黑盒重型求解器带来的不确定性与跨平台依赖，v3 采用**确定性迭代重加权槽位分配算法 (Iterative Reweighted Global Assignment)**：
1. **基线初始化**：将一级简码、规范单字与固定词全码置入前缀树作为固定锚点。
2. **多轮重加权迭代**：
   - 每轮遍历所有目标的候选码提议，根据当前树中各节点的拥塞度、碰撞质量与子树外部性动态计算净效用。
   - 依据 `[净效用降序 → 频率质量降序 → 目标字典序 → 码字典序]` 全序规则确定性分配候选槽位。
   - 更新树节点统计并进入下一轮收敛。
3. **确定性保证**：完全消除无序容器遍历，浮点数采用 `total_cmp`，同输入必得逐字节一致的输出。

## 4. 决策可解释性 (Explanation)

v3 编译器通过 CLI `--explain <word>` 提供透明的理由卡，任何槽位决定的原因均有据可查：

```text
=== Target: 时间 ===
Full Code: uijm
Legal Prefixes/Codes: [ui, uij, uijm, uj]
Selected Preferred Code: uj (rank 1)
Frequency Mass: 4.6000
Keystroke Benefit: +9.2000
Collision Cost: -0.0000
Prefix Congestion: -0.0000
Displaced Mass: -0.0000
XHUP Deviation: -1.1040
Migration Penalty: -0.0000
Final Objective Contribution: 8.0160
Rationale: Assigned to prefix uj with net utility +8.0160 (pattern II)
```

## 6. 兼容性与后续里程碑

- **`xhup_flow_static`**：永久保留 v1.0.0 静态行为与候选顺序，此 v3 成果不改变静态基线。
- **`xhup_flow`**：本阶段建立数据模型、Trie、全局求解器与基准工具，不涉及运行时 Lua 解码器修改，零生产行为破坏。
- **后续接入**：
  1. 候选注释清理（规范化为最小 ASCII 提示，如 `~dmz`）。
  2. mandatory Lua 合同。
  3. 基于本前缀树的 Key/Text 联合 Lattice 构建与有界 Beam/Viterbi 解码器。
