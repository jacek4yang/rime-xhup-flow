## 运行时身份与插桩

调试器确认本机 `PluginManager::LoadPlugins` 会在初始化期间加载系统插件并覆盖已预载的同名模块；`Lua::Lua()` 实际来自 `/usr/lib/x86_64-linux-gnu/rime-plugins/librime-lua.so`。系统包为 `1.16.1+dfsg1~git20250707-1build1`，该二进制 SHA256 为 `b6bbf0c499da589ccb0ed8f0ad6f692dd12eb2f12541c125dcaf2767d95027f2`。旧开发集记录只能作为这个系统插件环境的观测，不能归因于指定源码提交；保留结果并重新测量，不删除不利样本。

`runtime_module.h` 在显式指定 `XHUP_LUA_LIBRARY` 时只加载 `default` 与该 `lua` 模块，不运行系统插件扫描，并在初始化前后核验模块所属共享库的设备/inode。所有原生 C 测试入口和本地完整验收均使用它。未指定时仍允许系统环境，但输出真实加载路径。既有 CI 使用覆盖安装指定插件的方式，不把本机发现扩大为未经验证的 CI 失效断言。

`build-profile-runtime.sh` 从固定 Git 对象构建独立测试 VM/插件，不修改用户安装：Lua5.4.8 `6e22fedb74cf0c9b6656e9fce8b7331db847c605`，插件为上述支持提交。补丁在真实 allocator成功分配/释放、增量回收完成、代际 sweep完成、Memory.dict_lookup和Lua TableTranslator.Query入口计数。原子计数不改变回收策略；分配增长字节不冒充实际复制量。构建脚本、补丁、编译器和二进制哈希写入 provenance。插桩耗时不用于生产延迟比较。

`measure_runtime.py` 每次复制隔离部署，记录来源、首个/后续 session启动、Linux峰值RSS、逐键原生API延迟及可选工作量计数。仅物化实际可见页，避免前缀上的top256探测预热后续按键；覆盖单字、词简码、混码、连续输入、长串、尾码、中间编辑、128键、超限和连续退格。未模拟GUI显示、真实用户打字节奏或磁盘冷缓存。

指定插件的普通/插桩冒烟均已完成。插桩128键场景累计123,591次精确lookup，单键最多2,172次；199,359次成功分配/重分配，增量GC完成250次。随后学习关、学习开、Static和插桩各完成5个独立进程、每进程10轮的可见页测量，源码为 `843696eccb97328e1baea5969728c5f032fb025f`。错误来源的首次插桩输出 `profile-smoke` 仍保留，不用于基线；优化后的配对尚未开始。

计数器真实VM测试通过：两轮各保留并释放1MiB字符串，停止GC期间不计回收，显式增量/代际回收各准确增加一次，lua_close后活跃字节归零。插桩VM下的原生 replay 129项也通过（`artifact://125`）。错误共享库身份实际以退出码2拒绝。C入口均通过 `-std=c11 -O2 -Wall -Wextra -Werror -fsyntax-only`；本地验收测试8项、质量工具测试17项通过。测量入口只接受已经提交且运行期间未变化的测量源码，单独记录其commit与文件哈希。

额外区分完整菜单和持续会话：`--complete-menu` 只在场景最终输入独立遍历至迭代器耗尽，100,000候选上限命中则拒绝完整测量结论；统计首屏处理加后续遍历的API工作时间，不包含日志输出，不能当作首屏等待。实际冒烟中 `ni` 有21,468项，遍历约3.906秒（同时运行开发集回放，只作功能证明）；所有11个场景均到达耗尽。`--sustained` 在同一原生session中重复场景并记录每轮当前RSS和Lua活跃字节，不能用不断销毁session的结果代替持久会话内存。

峰值RSS定义修正：极小验证程序在入口报告 `ru_maxrss=523672 KiB`，同一映像的 `/proc/self/status VmHWM=1792 kB`，说明前者可混入exec前启动器的高水位。新入口改读当前映像VmHWM；上述旧五轮的ru_maxrss值不用于产品峰值比较。原始输出仍保留。持续会话两轮冒烟的Lua活跃字节均为8,467,122、当前RSS均为38,856KiB；这不是长期无增长证明。
