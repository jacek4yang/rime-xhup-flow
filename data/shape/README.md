# XHUP 规范汉字形码数据

本目录保存 XHUP Flow 的规范汉字形码**唯一事实来源**(canonical data):`hanzi_shapes.tsv`。当前由 `xhup-core::XhupHanzi::shape_codes()` 经 `include_str!` 编译期嵌入消费。

## 语义边界

本数据描述「规范汉字 → 其被接受的形码集合」关系(Model A):

```text
XhupHanzi
    ↓
&[ShapeCode]     // 非空、规范排序、无优先级语义
```

形码是**字形属性**,与读音无关:同一字的多个形码是上游收录的可接受拆字变体。本层**不**包含:

- 首选/主形码语义(来源无优先级证据;Rime 权重主要随读音频率变化,不构成形码优先级);
- 字根/拆分名称、首根、末根、助记等 root 元数据(两键形码不足以断言这些语义,属未来独立数据层);
- 读音、权重、源行序等来源字段(推导时有意丢弃);
- 全码(FullCode)组合——音码 × 形码的组合语义由后续专项 PR 定义。

## 文件与格式

`hanzi_shapes.tsv`:UTF-8、纯 LF 行尾、文件以单个换行结尾;每行两个 TAB 分隔字段:

```text
字<TAB>形码(恰好两个小写 ASCII 键)
```

排序:字符组按 Unicode 标量值全局严格升序;组内形码按字节序严格升序;无重复 `(字, 形码)` 对;每字至少一行。

规模:**8666 行,8105 个唯一规范汉字,670 个不同形码**。每字形码数分布:

```text
1 个: 7545 字
2 个:  559 字
3 个:    1 字(贯 -> gr, tr, vr)
```

共 560 字有多个形码变体。

## 上游来源与推导

- 来源仓库:`boomker/rime-fast-xhup`
- 固定 Git Blob:`3c2773335c8108bbe896b9af588d619e22045132`
- 源文件:`flypy_chars.dict.yaml`,SHA-256 `5eeda7a9976cf7d8ed1bc487bdccc02d7f423425515d814309328ff61b6b4291`
- 溯源记录:见仓库根 `NOTICE.md`

推导规则(投影):

```text
解析源行(字、音码、形码、权重)
→ 仅保留 字 ∈ 规范 XhupHanzi 8105
→ 丢弃音码、权重、源行序(非规范形码事实)
→ 投影去重 (字, 形码)
→ 按上述规范排序
```

源表共 8208 个唯一字符;规范汉字 8105 全覆盖(缺失 0);**103 个 8105 外源字符不纳入**(粤语字、生僻/古字、日本汉字等),本数据不扩大汉字域。

审计确认 21 个字的形码子集在源表中按读音行分布不同(如 仡 ge→{rq,ry} yi→{rq})。这是上游变体行的收录粒度差异,不是形码对读音的语义依赖;规范模型取**字级并集**,相应接受 17 个源表未逐行列出的读音×形码组合(仅审计上下文,不产生运行时 FullCode 组合)。
