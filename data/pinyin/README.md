# XHUP 规范输入音节清单

本目录保存 XHUP Flow 的规范输入音节**唯一事实来源**(canonical data):`xhup_input_syllables.txt`。未来的 Rust 编码器、分析器、Rime 产物与 trainer 均以此为准;当前由 `xhup-core::XhupInputSyllable` 经 `include_str!` 编译期嵌入消费。

## 语义边界

`XhupInputSyllable` 是**输入法域**概念:XHUP Flow 接受的、属于当前规范小鹤可编码输入清单的归一化无调拼音拼写。它不声称覆盖全部语言学合法普通话音节,也不是标准书面汉语拼音的完整清单:

```text
有上游来源支持的归一化拼音形式
        !=
XHUP 可编码的输入音节
```

## 文件与格式

`xhup_input_syllables.txt`:UTF-8、纯 LF 行尾、文件以单个换行结尾;每行一个归一化音节;全部小写 ASCII(`[a-z]+`);按字节序严格升序;无重复、无空行、无注释、无首尾空白。共 406 行。

## 规范化契约

清单本身已是归一化数据。推导时使用的归一化规则:

1. 去除声调符号;
2. 全部小写;
3. 书面/带调 `ü` 族转换为输入法 `v` 表示:`lǜ→lv`、`nǚ→nv`、`lüè→lve`、`nüè→nve`;
4. `j/q/x/y` 后的常规拼写**不**改写:`ju qu xu yu jue que xue yue jun qun xun yun` 保持原样;
5. 最终拼写必须匹配 `[a-z]+`。

`XhupInputSyllable` 的解析为精确匹配,不做任何归一化:`"lv"` 合法,`"lü"`、`"LV"` 非法。


## 项目编码边界排除

以下 5 个形式**有上游来源支持**,但当前规范小鹤布局没有支持的编码路径(既非零声母音节,也无法按声母+韵母结构组合),故不纳入本清单。这是**项目编码边界**,不是对其语言学合法性的否定;未来显式立项的扩展层可重新审议:

- `m`、`n`、`ng`、`hng`:成音节辅音/特殊感叹形式(呣、嗯、哼);
- `ea`:ê(欸)的键盘表示(GF 3006-2001 中 ê 表示为 EA),当前布局无对应编码路径。

## 显式暂缓的扩展音节

`biang`、`cei`、`fiao`、`hm`、`nun`、`rua`、`tei`、`zhei` 等仅出现于审计/交叉核对层的读音,本清单有意不收。本 PR 建立保守的现代 XHUP 基础清单;是否支持由未来的扩展层显式决策,当前不预留扩展设施。

## 交叉核对来源(非成员资格权威)

- `iDvel/rime-ice` @ `fbb516b2786e4d5444383706d13c31c2e4d10c08`(`cn_dicts/8105.dict.yaml`,GPLv3):仅作真实输入法一致性证据,**不复制其数据**;其同样停用了 `m/n/ng/hng` 等行(嗯→`en`),与本边界一致。
- `pinyinsyllables.csv`(cjklib 转录 ISO 7098:1991 附录 A 的 `I` 集,408 项):仅作历史标准对照,本清单不从其推导。
- `kXHC1983.txt`、`kMandarin.txt`、`pinyin.txt`(同上游仓库):仅作审计/交叉核对,不并入本清单。
