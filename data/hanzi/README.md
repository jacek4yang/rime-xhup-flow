# XHUP 规范汉字读音数据

本目录保存 XHUP Flow 的规范汉字读音**唯一事实来源**(canonical data):`readings.tsv`。未来的 Rust 编码器、分析器、Rime 产物与 trainer 均以此为准;当前由 `xhup-core::XhupHanzi` 经 `include_str!` 编译期嵌入消费。

## 语义边界

本数据描述「规范汉字 → 其上游来源支持的归一化无调读音」关系,是**汉字读音域**概念,刻意保留来源事实,不做语义替换:

```text
HanziReading(规范汉字数据中的归一化读音)
        !=
XhupInputSyllable(XHUP 可编码的输入音节,见 data/pinyin/)
```

两者通过 `HanziReading::to_input_syllable()` 作精确可选转换;当前有 6 个 `(字, 读音)` 关系落在 406 音节清单之外(见下文「非 XHUP 边界」),它们仍是合法的 `HanziReading`。**不**引入 `m→mu`、`n→en`、`ng→eng`、`hng→heng`、`ea→ei` 之类的回退/替换——那是语义读音变更,不是归一化。

声调信息被有意折叠:XHUP 当前无声调域,同一字的不同调同形读音(如 `上 shǎng/shàng`)合并为一个归一化读音。

## 文件与格式

`readings.tsv`:UTF-8、纯 LF 行尾、文件以单个换行结尾;每行三个 TAB 分隔字段:

```text
字<TAB>归一化读音<TAB>角色
```

- 字符字段:恰好一个 Unicode 标量值;
- 读音字段:小写 ASCII `[a-z]+`;
- 角色字段:恰为 `primary` 或 `alt`;
- 排序:字符组按 Unicode 标量值全局严格升序(不保留上游文件的 URO/扩展两段式顺序);组内 `primary` 行在前,`alt` 行按字节序严格升序;
- 每字恰好一个 `primary`;无重复 `(字, 读音)` 对。

规模:**8580 行 = 8105 个 primary + 475 个 alt;8105 个唯一字符**。每字的规范读音为并集:

```text
normalize(kTGHZ2013 该字读音集) ∪ { normalize(kMandarin_8105 主读音) }
```

主读音已在 kTGHZ2013 集合中时只标一行 `primary`,不重复建 `alt` 行。审计确认有 **126 字**的归一化主读音不在其 kTGHZ2013 集合内(如 `欻 chua/xu`、`剋 ke/kei`、`嗲 die/dia`),这些字同时保留 primary 行与全部字典 `alt` 行;这 126 个主读音全部另有上游次级来源(`kXHC1983`/`kMandarin`/`pinyin.txt`)佐证。

字符成员资格仅由本文件首列唯一集合承载,没有也不应有第二份字符清单文件。

## 规范化契约

文件本身已是归一化数据。推导时使用的归一化规则(与 `data/pinyin/` 一致):

1. 去除声调符号;
2. 全部小写;
3. 书面/带调 `ü` 族转换为输入法 `v` 表示:`lǜ→lv`、`nǚ→nv`、`lüè→lve`、`nüè→nve`;
4. `j/q/x/y` 后的常规拼写**不**改写;
5. `ê` 族转换为键盘表示 `ea`;
6. 最终拼写必须匹配 `[a-z]+`。

## 上游不确定性标记(仅溯源,不进运行时)

`kMandarin_8105.txt` 注释中的不确定性标记是上游策展元数据,不进入 `readings.tsv` 的任何字段。审计统计(Phase 1 脚本计数口径:`?->` 与 `->` **互斥**——先判 `?->`,含 `?->` 的记录不再计入 `->`;`=>` 与 `<-` 独立计数,可与前者重叠):

```text
?-> : 32    主读音存疑的上游建议(如 丧 sàng ?-> sāng)
->  : 378   不含 ?-> 的建议/补充读音(如 倞 jìng -> liàng)
=>  : 112   扩展字 ↔ 规范字映射
<-  : 0     (仅图例行出现)
```

凭固定提交即可完整重建这些标记;本 PR 不引入运行时不确定性标志。

## 非 XHUP 边界(再生后已机械验证)

当前规范并集中恰好 **6 个 `(字, 读音)` 关系**不属于 406 音节清单,涉及 **5 字**:

```text
呒  m    alt        哼  hng  alt
呣  m    primary    嗯  n    primary
欸  ea   alt        嗯  ng   alt
```

其中 **2 个主读音不可编码**(呣 `m`、嗯 `n`);恰好 **2 字当前没有任何 XHUP 可编码读音**:`呣`(`[m]`)、`嗯`(`[n, ng]`)。这些形式有上游来源支持,其不可编码性是**项目编码边界**(同 `data/pinyin/` README),不是语言学否定;未来显式立项的扩展层可重新审议。下游代码不得假设「每字必有可编码读音」。
