fix(android): 按实测校正 APK 体积上限,并记录 582 MiB 的真实发现

上一版把上限设为 256 MiB,依据是**估算**。CI 实测 APK 为
**610,398,037 字节 = 582.1 MiB** —— 估算错了 2.3 倍。

这不是 CI 抖动,而是一个**真实的移动端交付问题**:
- universal APK 打包 **4 个 ABI**(arm64-v8a / armeabi-v7a / x86 / x86_64),
  每个约 146 MiB;
- workspace **没有配置 release profile**(无 LTO、无 strip),
  因此 .so 保留了全部符号;
- 4 x 146 MiB ≈ 582 MiB。

本次处置(克制):
- 把上限按**实测值**校正为 768 MiB(约 +30% 余量),理由写入 YAML 注释;
- **不**顺手做 ABI 拆分或 release profile 调优 —— 那改变构建配置与产物
  形态,属产品决策,且可能影响发布签名与升级路径;
- 明确写入注释:该上限**不是**体积预算,只防灾难性劣化。

582 MiB 降到合理范围是**独立的待办**(ABI 拆分 + release LTO/strip),
已在 Issue #83 记录,附本次实测数据与成因分解。

教训:门槛值不应凭估算设定。本步骤的价值恰恰在于它用真实数据推翻了我的
估算 —— 这是「先度量、后设门」纪律的一次正例,尽管代价是一次 CI 失败。
